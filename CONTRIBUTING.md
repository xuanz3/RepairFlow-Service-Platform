# Contributing

RepairFlow uses issue-driven development and reviewed phase branches.

## Workflow

1. Start from a GitHub issue with measurable acceptance criteria.
2. Use a `phase-x/`, `feature/`, `fix/`, `test/` or `docs/` branch.
3. Keep each commit focused and use Conventional Commit prefixes.
4. Add or update tests with behavioural changes.
5. Open a pull request and record verification evidence.
6. Do not merge when required checks fail.

## Commit examples

- `feat(mobile): persist offline intake drafts`
- `test(sync): cover duplicate repair operations`
- `fix(desktop): retain selected case after reconnect`
- `docs(adr): record attachment conflict policy`

## Product media

Only final, meaningful product media is retained. Temporary captures, duplicate views and unreviewed generated data are not committed.
