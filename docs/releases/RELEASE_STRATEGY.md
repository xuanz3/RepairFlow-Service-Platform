# Release Strategy

RepairFlow uses semantic versioning and GitHub Releases.

- `v0.0.1` establishes the product and repository baseline.
- `v0.1.0` and `v0.2.0` expose foundation and service capabilities.
- `v0.3.0` and `v0.4.0` expose desktop and mobile previews.
- `v0.5.0` and `v0.6.0` validate offline behaviour and reliability.
- `v0.9.0-rc.n` identifies release candidates.
- `v1.0.0` is published only after the full acceptance matrix passes.

Each release contains a clear scope, verified changes, installation or execution notes, known limitations and links to the relevant milestone and pull requests.
