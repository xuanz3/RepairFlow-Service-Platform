# Interface and Motion Direction

## Product character

RepairFlow should feel precise, calm and dependable. It is a workshop tool, not a marketing surface. Information hierarchy, evidence clarity and recovery states take priority over decoration.

## Desktop direction

- Three-region layout: navigation, working surface and contextual inspector
- Compact but readable density
- Clear case status, assignment and sync state
- Keyboard-first navigation for frequent workshop actions
- Neutral surfaces with one restrained accent and semantic status colours
- No decorative dashboards, fake data visualisations or excessive card grids

## Mobile direction

- Platform-familiar navigation and controls
- One primary task per capture screen
- Large touch targets and clear permission alternatives
- Persistent local-save and sync feedback
- Camera and annotation actions remain reachable with one hand

## Motion rules

- Motion communicates state change, hierarchy or direct manipulation
- Use short opacity and transform transitions for most feedback
- Use spring motion only for direct manipulation and sheet movement
- Never delay a critical repair action for decorative animation
- Honour system reduced-motion settings
- Avoid continuous background movement, large zoom transitions and blur animation

## Accessibility baseline

- Full keyboard path for the desktop core workflow
- Visible focus states
- 100%, 150% and 200% desktop scaling checks
- VoiceOver and Android accessibility labels for mobile core controls
- Status is never communicated by colour alone
- Destructive actions require clear confirmation and recovery guidance
